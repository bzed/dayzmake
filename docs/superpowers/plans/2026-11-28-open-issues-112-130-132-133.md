# Open issues #112, #130, #132, #133 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the four open, actionable issues of bzed/dayzmake: the flaky navmesh watchdog (#130), the `image` 0.24 pin (#132), the unpublished navmesh test support (#133) and the 3.1.0 polish list (#112).

**Architecture:** Four independent tasks on one branch, one commit each (Task 4 may be two commits, see there). #133 moves the fake data server and the synthetic world from `crates/dayzmake-core/tests/support/` into a feature-gated public module `navmesh::testing`; the existing tests keep including the same files by `#[path]`, so there is one source and the default `cargo test` still runs them. #132 is a dependency bump that breaks the core's public API (`pub use image`), so the next core release is 0.4.0.

**Tech Stack:** Rust 1.99 (edition 2024), Cargo workspace, `image` 0.25, `peg`, `cargo deny`, mdBook.

**Spec:** the issue texts (`gh issue view <n> -R bzed/dayzmake`). Not in scope: #128 (its last comment rules it data and keeps it open as a record); #123 and #124 were closed as wontfix on 2026-11-28. The issues on `upstream` (KoffeinFlummi/armake2) are not ours.

## Global Constraints

- All of `AGENTS.md` applies. In particular: test first; `make check` passes per commit; no `unwrap`/`expect`/`panic!`/unchecked indexing in library code; `#[expect(lint, reason = "...")]`, not `#[allow]`, except the existing `#![allow(dead_code, reason = ...)]` of the shared support files; public items have rustdoc; new public types `#[non_exhaustive]`.
- Temporary and build folders under `/tmp` or `/var/tmp`, never `$HOME`.
- Documentation in ASD-STE100 (about 80 %).
- New dependency versions: review the crate (source, RustSec, maintenance, licence) and write the result into the commit message; run `make deny` after each `Cargo.toml` change.
- Branch: `fix/open-issues-2026-11-28` from `main`. One PR at the end, body `Closes #112, closes #130, closes #132, closes #133.`

## Review Focus

1. **The fake server inside the library panics on a malformed client frame.** As library code it is reachable by downstream programs; a short or huge frame from a buggy client must end that connection, not the process. Test in Task 3 (`fake_server_survives_a_garbage_client`).
2. **A downstream crate with `image` 0.25 still gets two versions.** Both the core and the CLI must move; `cargo tree -d -i image` must show one version. Check in Task 2, step 5.
3. **`image` 0.25 default features add `avif`/`rayon` (rav1e, a heavy build) or drop a format the CLI decoded before.** The format list stays the 0.24.9 default set. Test in Task 2 (`img2paa_reads_every_format_of_image_0_24`).
4. **`make features` (no default features) no longer builds** because `navmesh::testing` or `extern crate self` leaks outside its feature. Covered by the new `make features` lines in Task 3.
5. **The watchdog no longer catches a real deadlock.** It must still fail, not hang forever: the limit is finite (600 s). Covered by the unchanged `generate_watched` behaviour; reviewed in Task 1.
