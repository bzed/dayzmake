# Fixes for Issues #11–#23 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Fix the eight bugs found while fixing #3–#9:
- #18: a failed build destroys or leaves behind the target PBO.
- #17: a Proton `$PBOPREFIX$` can escape the sandbox.
- #15: untrusted text reaches the terminal unescaped.
- #13: C1 control characters can end up in unpacked file names.
- #11: `build .` fails when there is no `$PBOPREFIX$`.
- #12: preprocessor errors use 0-based line numbers.
- #14: unknown packing methods are relabelled on write.
- #16: `P3D::write` accepts inconsistent models.

**Architecture:** Nine independent fixes, one task and one commit each. They are ordered by impact: data loss and path safety come first.

**Tech Stack:** Rust 1.99, the dayzmake workspace (`crates/dayzmake-core` + CLI crate), `insta` snapshots.

**Spec:** GitHub issues https://github.com/bzed/dayzmake/issues/11 to /23. The issue text is binding where this plan is silent.

## Global Constraints

- Runs after PR #10 (issues #3–#9) is merged. Branch `fix/issues-11-18` from `main`.
- All `AGENTS.md` rules apply. `make check` passes after every task, and Windows CI is green before merge. `tests/cli.rs` and `pbo_api.rs` run on Windows, so names Windows rejects (C0 controls, `<>:"/\|?*`) are `#[cfg(unix)]`.
- Snapshots change only where a task names them; review each `.snap.new` by hand.
- Commit subjects end with `(#N)`, and the body has `Fixes #N`. Implementer commits carry their own accurate model attribution.
- No new dependency without the AGENTS.md review (`tempfile` is already a dependency of the CLI crate's tests; check before using it in `src/`).

## Review Focus

1. **Atomic output (#18):**
   - A failed command never truncates an existing target.
   - A successful one replaces it in one rename.
   - A temp file left by a crash is never mistaken for the target.
2. **Paths (#17, #13):** checks use the same rules everywhere. Nothing is created outside the target or sandbox root, for any prefix or entry name.
3. **Escaping (#15):** every place that shows a path from a file goes through `printable`. Stored values stay raw, only their display is escaped.
4. **No CLI/MCP output change** beyond the ones each issue asks for.

### Task 1: Atomic output for build, pack and the single-file commands (#18)

**Files:** `src/cli_io.rs` (new `AtomicTarget`), `src/run.rs`, `src/mcp.rs`, `src/commands/*.rs` where a target is written; test `tests/cli.rs`, `tests/golden_mcp.rs`.

**Interfaces (CLI crate):**

```rust
/// A target file written atomically: data goes to a temp file next to `path`, which
/// `commit` renames over `path`; dropped without `commit`, the temp file is removed.
pub struct AtomicTarget { /* path, temp path, File */ }
impl AtomicTarget {
    pub fn create(path: &Path, force: bool) -> Result<AtomicTarget, Error>; // keeps today's "already exists. Use --force" check and text
    pub fn commit(self) -> Result<(), Error>;                              // fsync + rename
}
impl Write for AtomicTarget;
```

The temp file lives in the target's directory as `.<name>.dayzmake-tmp-<pid>-<n>`. `create_target` callers (`get_output`, MCP `create_target`) switch to it. `run_command` commits only after the command returned `Ok`. Stdout output is unchanged.

- [ ] **Step 1: Failing tests.**
  - `failed_build_keeps_the_existing_target`: write `out.pbo` with known bytes, then run `build -f` on a folder whose `config.cpp` has a parse error. Expect exit 1, and `out.pbo` byte-identical to before.
  - `build_of_a_missing_folder_creates_no_target`: `build nodir out.pbo` creates no `out.pbo` and leaves no temp file in the directory.
  - `successful_build_replaces_the_target`.
  - MCP: a `pbo_build` failure keeps the existing target.
  - The same failing-input check for `rapify -f` over an existing `.bin`.
- [ ] **Step 2: Run** the tests. Expected: they FAIL.
- [ ] **Step 3: Implement.** On Windows, `rename` over an existing file needs `std::fs::rename`, which replaces on Windows since Rust 1.5 via `MoveFileExW` with `MOVEFILE_REPLACE_EXISTING`. Check the std docs and say so in the report.
- [ ] **Step 4: Run** `cargo test --workspace --locked`. Expected: PASS, no snapshot changes. `make check`.
- [ ] **Step 5: Commit**: `fix: build and conversion outputs are written atomically (#18)`.
