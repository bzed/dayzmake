### Task 3: Include search does not walk the working directory (#66)

Maintainer decision (2026-11-16): the implicit `.` include folder (`src/run.rs:215`) is only checked directly
(`./<include path>`), never walked recursively; `-i` folders keep the recursive suffix search, but `search_directory`
(`crates/dayzmake-core/src/preprocess.rs` ~806) does not follow directory symlinks that lead outside the search root or
back into it (loops), and stops after a bounded number of visited entries (one documented constant; measure real `-i`
trees such as a P: drive copy first) with an error naming the include. Keep the API additive: if the library needs to
know which folder is the implicit one, add it to the options struct. Tests: a missing absolute include from a cwd with
a large tree fails fast; a file directly at `./DZ/data/x.hpp` is still found without `-i`; an include found through an
`-i` folder (nested, case-insensitive) still works; a symlink loop under an `-i` folder terminates. README `## Changes`
(behaviour change). Commit `fix: a missing include no longer searches the whole working directory (#66)`.
