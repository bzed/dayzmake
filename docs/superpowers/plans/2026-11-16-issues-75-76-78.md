# Issues #75, #76, #78: PAA mipmap storage and offset tagg, implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `Paa` knows for every mipmap whether its bytes are LZO-compressed, so writing never mislabels a
mipmap (#76) and decoding works on compressed mipmaps (#78); reading drops the `GGATSFFO` offset tagg so writing
does not duplicate it (#75).

**Architecture:** All changes are private to `crates/dayzmake-core/src/paa.rs`: replace `mipmaps: Vec<Vec<u8>>`
with `mipmaps: Vec<Mipmap>` where `struct Mipmap { data: Vec<u8>, lzo: bool }` (private). No public API change.

**Tech Stack:** Rust 1.99, `lzo1x` 0.2.2.

**Spec:** issues bzed/dayzmake#75, #76, #78 (`gh issue view <n> -R bzed/dayzmake`).

## Review Focus

1. A flagged (LZO) mipmap read from a file: `Paa::read` keeps decompressing it (current behaviour, `lzo: false`
   after read), so `to_dynamic_image` and `write` behave as today.
2. `lzo_compress` then `to_dynamic_image` without writing: same pixels as without compression (#78).
3. An unflagged mipmap shorter than its raw size (accepted by `read`): written back unflagged (#76), and
   `to_dynamic_image` on it gives the existing "does not fit" error, not a panic.
4. Read → write → read of a file with a `GGATSFFO` tagg and other taggs: exactly one `GGATSFFO`, with correct
   offsets; other taggs kept in order (#75).
5. Decompressing for decode respects the same size budget as reading (no unbounded allocation).

    unflagged and 1000 bytes; `Paa::read` → `write` → the first mipmap header's width has bit 0x8000 clear.
  - `compressed_paa_decodes_without_a_round_trip`: `from_dynamic_image` of a deterministic 256×256 gradient
    (DXT5) → `to_dynamic_image` succeeds and equals the decode of the same `Paa` written and read back.
  - Run: FAIL (both).

  (delete the length heuristic); `to_dynamic_image` decompresses the first mipmap first when `lzo` is set, via
  the existing `decompress_mipmap` (with `MAX_PAA_TOTAL` as budget). Offsets/sizes in `write` use `data.len()`.
- [ ] Run the new tests, then `cargo test --locked -p dayzmake-core` and `cargo test --locked --test paa --test golden_cli --test golden_mcp`: PASS, no snapshot changes.
