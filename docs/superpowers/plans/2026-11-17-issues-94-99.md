  - `#[expect(..., reason)]` instead of `#[allow]`.

## Review Focus

1. Config files with CRLF line ends, or no newline at the end of the file: #94 locations and the #95 last-entry rule
   behave the same as with LF. Tasks 1 and 2 test both.
2. A hostile PBO whose includables are huge, truncated or nested in `..` chains that leave the PBO root: Task 8
   tests the byte cap, truncation and escape refusal.
3. A grep match on a line with multibyte UTF-8 at the cut point: Task 5 tests that the cut lands on a character
   boundary and doesn't panic.
4. `api config` load order when a mod's addon is required by vanilla, or the reverse: Task 7 tests both directions
   of the global sort.
5. Extract with a target folder inside the source, without `-f`: Task 6 tests that nothing is written.

### Task 2b: overflowing float literals as in CfgConvert (#102)

Added while Task 2 ran: CfgConvert writes an f32 infinity for `1e999`, while dayzmake rejects it.

**Files:** `crates/dayzmake-core/src/config.rs` (the float action that raises `Invalid float "...": out of range`, and
the float writer of derapify); tests next to `out_of_range_floats_are_errors` and the CfgConvert reference tests;
`tests/fixtures/bi/cfgconvert/`; README line 69 ("never infinity or NaN"); the book's config page.

- [ ] Reference run with CfgConvert. Use the same Proton setup as Task 2 (Proton 10.0 + `xvfb-run`, see the fixtures
  README). Inputs: `a = 1e999; b = -1e39; c = 1e-999; d = 3.4e38;` in a class. Record the binary values (f32 bits)
  and add the input and output as fixtures.
- [ ] Ruling: follow CfgConvert. An overflowing literal rapifies to the f32 value CfgConvert writes (±infinity),
  with no error. Underflow follows CfgConvert too. Derapify writes infinity in a form that dayzmake's own parser reads
  back to the same f32. Pick the form CfgConvert's input accepts, if one exists (check `1e999` itself, which works);
  otherwise use `1e39` / `-1e39`. Then `derapify` followed by `rapify` round-trips bit for bit. A trailing-text case
  such as `1e999x` keeps whatever it does today.
- [ ] Tests first. Change the `out_of_range_floats_are_errors` assertions that become wrong, and add round-trip
  tests. They FAIL first. Implement. PASS, then `make lint`.
- [ ] Commit `fix: an overflowing float literal becomes infinity, as in CfgConvert`, with `Fixes #102`.
